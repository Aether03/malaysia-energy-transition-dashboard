## Recommendation

**Updated 2026-10-03 (main session, after the agent's search): Singapore (EMA) qualifies on all four criteria.** Criterion (b) was read from the primary source in a real browser. https://www.ema.gov.sg/terms-of-use loaded with no CAPTCHA; the agent's tool was stopped by a bot check. The page has **two** sections, which explains the conflicting snippets:
- §6 "Intellectual Property" covers the **website's materials** ("no part of The Website may be reproduced or reused for any commercial purposes whatsoever without our prior written permission").
- **"Terms of Use of Datasets"** covers the **datasets**. EMA grants "a worldwide, perpetual, royalty-free, non-exclusive licence to use the datasets", and §3 says "You can use, access, download, copy, distribute, transmit, modify and adapt the datasets, or any derived analyses or applications, whether commercially or non-commercially". This is the **Singapore Open Data Licence v1.0**.
- **Conditions:**
  - §9: a conspicuous attribution notice with a link to the licence.
  - §7: no implied endorsement.
- **Scope:** the licence applies to "the datasets on the relevant Websites", defined as this website or other websites owned by EMA. The half-hourly page (https://www.ema.gov.sg/resources/statistics/half-hourly-system-demand-data) names no separate licence. So the dataset terms are read as applying to it: **Recommended**, with a small residual ambiguity, noted in `DATA_LICENSES.md` if it is adopted.

**Decision for Amirul (M3 plan Q4):** add Singapore as the second grid (EMA files directly, cited as EMA under SODL v1.0), or keep P4 Thailand-only. No other ASEAN grid qualifies.

## Notes and unverified items

- **EMA site bot protection.** HTML pages on ema.gov.sg (including the terms page) show an Imperva "additional security check". I stopped there and did not try to bypass it. The `.xls` file URLs respond normally to plain requests.
- **EMA licence quotes are second-hand.** They came from a search-engine summary, not a fetched page. Treat them as leads, not proof. Primary sources actually read: data.gov.sg Open Data Licence (https://data.gov.sg/open-data-licence), EMC terms, IEMOP legal notice. Those three were extracted via WebFetch; re-read the wording before quoting in the repo.
- **EMA file format.** One workbook per week (Mon–Sun), three columns per day (System Demand Actual, NEM Demand Actual, NEM Demand Forecast), rows are period-ending 00:30 to 24:00. Pre-December-2014 file names use `DD_Mon_YYYY.xls`. I read one sample file (20240101.xls, 63 KB) and compared its first values with SASEA (5,646.0 MW at period ending 00:30 on 2024-01-01 matches). I did not check that every weekly file for 2023–24 exists; only the six dates listed above were probed.
- **System Demand vs NEM Demand.** "System Demand" includes embedded generation, so it is higher than NEM Demand (5,646 vs 5,546 MW in the sample). Choose one for the dashboard and label it.
- **Singapore data.gov.sg gap.** Monthly peak only, ending 2021-07; last updated 2024-06-06. It is licensed under the Open Data Licence but fails (a).
- **IEMOP window.** The `min_date` on the page (07/04/2026) and the page count (4 pages) agree with a ~90-day rolling window. IEMOP's other series (prices, schedules) were not checked for older history; the regional-summary file is the only one carrying demand-like fields (MKT_REQT, LOAD_BID, GENERATION).
- **Viet Nam / Indonesia.** Not reachable from this machine (ECONNREFUSED on nsmo.vn, pln.co.id). It may be a geo or network block; re-test from another network before treating these as closed. No sign of an open licence in any case.
- **NGCP "All rights reserved" hourly 2013–2024** comes from an aggregator listing (ost.ecosyste.ms "Awesome Grid Model Data"); not confirmed at NGCP.
- **Not searched in depth:** Kaggle, Mendeley Data and Figshare beyond keyword searches; Zenodo API queries for Philippines, Vietnam, Indonesia, Singapore, Malaysia and ASEAN hourly demand returned only SASEA and the Thai record among ASEAN items.
